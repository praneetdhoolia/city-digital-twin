# The Python half of the toolchain pin.
#
# `.claude/CLAUDE.md`: "The toolchain is pinned, and a toolchain change is a
# model change." That was true of the JDK, pt2matsim, Maven and the MATSim run
# stack - `src/setup/bootstrap_toolchain.py` fetches them and records a sha256
# for each in `.tools/toolchain.json` - and it was NOT true of Python, which
# builds every input the simulator reads. A geopandas or shapely release that
# changes a spatial predicate, a pandas release that changes a groupby default,
# a numpy release that changes an RNG stream: any of them moves the synthetic
# population, the zone joins or the network layers, and the reproducibility
# gate would not see it, because nothing said which version produced the
# package.
#
# So this file is the same kind of artefact as `.tools/toolchain.json`, and
# CHANGING A PIN HERE IS A MODEL CHANGE: re-run the affected builders,
# regenerate `data/MANIFEST.csv`, and log it in `DECISIONS.md` §14 beside the
# toolchain entries.
#
# WHAT IS PINNED. Exactly what this repository imports, plus what those need to
# import in turn - not the whole of `pip freeze`, which would pin a
# workstation's unrelated packages into the contract.
# `tests/check_requirements.py` proves the first half: every third-party
# top-level import under `src/`, `tests/`, `cities/` and `run.py` has a line
# here, and every line is exactly pinned.
#
# NO HASHES, AND THE REASON PREVIOUSLY GIVEN HERE WAS FALSE. This block said
# the Python package index sits outside the network sandbox; `pypi.org` and
# `files.pythonhosted.org` have been on the allowlist in `.claude/settings.json`
# since 10 August, so nothing about the sandbox prevents a hash being taken or
# verified here. The honest reason is narrower: `--require-hashes` is all-or-
# nothing across the file and applies transitively, so it means pinning every
# transitive dependency by digest as well, on every platform this package is
# installed on. Exact version pins are what is stated today; hashes are a
# follow-up with a real cost, not a claim blocked by a sandbox rule.
#
# Python itself: 3.14 (CI's `actions/setup-python`; recorded 8 September 2026
# against 3.14.4 on the workstation the package was last built on).
#
#     pip install -r requirements.txt
#
# The lighter CI jobs install only the one or two packages they need and pass
# this file as a CONSTRAINTS file (`pip install -c requirements.txt ...`), so
# they get the pinned versions without the geospatial stack, and a drifted pin
# fails there too.
