# docs/ — the simulator and its results

Everything about the twin that is not one city's: what it is for, where it
stands, what runs next, why every value is what it is. What describes a city —
its study area, its sources, its targets, the reference generated from its
inputs, its data requests, its frozen dossiers — is under that city at
[`cities/<city>/docs/`](../cities/newcastle/docs/README.md). Install and run
is the root [`README.md`](../README.md); the conventions are
[`.claude/CLAUDE.md`](../.claude/CLAUDE.md).

| | Read it for |
|---|---|
| [`GOAL.md`](GOAL.md) | **What the twin is for** — the ten hard requirements, the gate loop, the monitoring rule. Read first. |
| [`STATUS.md`](STATUS.md) | **The board, one page** — the twelve-mode scoreboard from the latest reading, where the build is, the runs on disk, what is next. Its blocks are generated by `python src/analyse/build_status_board.py`. |
| [`lane.json`](lane.json) | **The lane** — the single next task with its cost and blocker, and the decisions the user has not yet taken, with their options. Rendered into the board's *Next* and the brief's §1; kept with `src/analyse/lane.py`. |
| [`NEXT_AGENT_BRIEF.md`](NEXT_AGENT_BRIEF.md) | The pointer the last session left: the facts that expire and how to re-derive them, the lane, the traps, the standing approvals. Rewritten at every `/handoff`. |
| [`positions/`](positions) | **The current truth per topic**, one page each — ride, walk and bike, taxi, light rail and ferry, public transport, signals, population, network, sampling, seed and choice set, runs and economics, monitoring. Every figure carries its source; a page is at most 130 lines and 14,000 bytes. |
| [`DECISIONS.md`](DECISIONS.md) | **The record**: every value that is not observed and every decision, dated, with its rationale and sweep. Append-only and frozen; enter through its topical index or a position page — never read it whole. |
| [`run_families.json`](run_families.json) | The family ledger: every change to the plans or the network opens a comparability class, and nothing compares across one. |
| [`reports/`](reports/README.md) | The dated `/project-report` assessments (the newest three kept in the tree), the recommendation ledger [`recommendations.json`](reports/recommendations.json), and the standing reference library the research passes start from. |
| [`HANDOVER_CONTRACT.md`](HANDOVER_CONTRACT.md) | How a session opens and closes: the reading budget, the trust order, the four state-of-the-project questions, the facts that expire, the decisions asked once, the gate. |

## How the documents relate

`GOAL.md` states the target. `STATUS.md` measures distance to it and is the only
document that must be read every session. `lane.json` says what is next and what
it waits on. A position page is the current truth for one topic and is rewritten
whenever a session touches that topic; the record is where the history and the
rationale go, and it is never rewritten. A number in a living document is a
claim about an artefact: `tests/check_doc_currency.py` fails when the two
disagree (the claims are the city's, `cities/<city>/tests/doc_currency.json`),
`tests/check_doc_shape.py` keeps each document the shape it was designed to be
(the rules are the framework's, `tests/doc_shape.json`), and
`tests/check_doc_links.py` fails on a link that resolves to nothing.

Nothing here is a result until a run's `_run.json` says `ran_to_last_iteration`.
A run stopped at a gate carries a record too, citable at its `reached_iteration`
and nowhere past it.

## The framework and the portable contract

The framework — `run.py`, `src/`, `config/schema/`, `tests/` — names no city.
`src/city.py` resolves the selected city's inputs (`CITYSIM_CITY`, default
`newcastle`), the simulator's documents (`city.docs()`) and the city's own
(`city.city_docs()`); nothing else knows where any of them lives.
[`config/schema/`](../config/schema) states what any city must supply:

| File | States | Generated by |
|---|---|---|
| `field.schema.json` | the shape of one controllable value: units, source class, the sweep a non-observed value must carry | — |
| `registry.schema.json` | the shape of one registry layer file | — |
| `city.schema.json` | a city's identity: CRS, base year, seed, the derived boundary, zone system, modes, day types, adapters, sources | — |
| `required_fields.json` | which field keys a city must declare, with units and value type | `python src/registry/render_schema.py` |
| `layers.json` | which city-relative artefacts the framework reads, found from its own `city.path(...)` calls | `python src/registry/render_schema.py` |
| `outputs/` | the schemas a run's own records must satisfy, checked at write time; a run that died must say why | — |

```bash
python src/registry/check_city.py --all       # every city, against all of the above
python src/registry/render_schema.py --check  # the generated halves are not stale
python src/run/session_gate.py --digest       # the session opener: goal, board blocks, machine, branch, PRs, lane
python src/run/session_gate.py                # every gate, one line each
```

**Editing the Java in VS Code.** The two source trees are compiled by
`src/setup/bootstrap_toolchain.py` against the pinned jars in `.tools/`; the
committed [`.vscode/settings.json`](../.vscode/settings.json) gives the Java
extension the same classpath after `python src/setup/bootstrap_toolchain.py --run-stack`.
The extension must itself run on JDK 25 or later (the pinned jars are class-file
version 69); set `java.jdt.ls.java.home` and `java.configuration.runtimes` in
your user settings to `.tools/jdk`, then *Java: Clean Java Language Server
Workspace*.
